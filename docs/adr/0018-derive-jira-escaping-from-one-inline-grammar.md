# Derive Jira escaping from one Jira inline grammar verified by re-parsing

Live Jira Server 8.20.10 renders Text Effects, links, autolinks, emoticons, dash substitution, and backslash escapes inside a Monospace Span, gates every Effect Delimiter by the same Unicode word-boundary rule inside and outside `{{...}}`, and refuses a Monospace Span whose braces touch a word character. jiro had grown three divergent copies of these rules (the Jira inline parser, the plain-text escaper, and the inline-code escaper) plus hand-written allowlists, so Canonical Jira Markup could drift from what Jira actually reads. jiro now keeps exactly one Jira inline grammar, shared by the Jira parser and every Jira renderer path, and defines escaping correctness as "re-parsing the rendered inline run with jiro's own Jira parser yields the intended semantic inlines". The renderer escapes predictively from the grammar, verifies once by re-parsing, falls back to encoding every hazard in that run and verifying again, and otherwise emits a literal-fallback warning; it never loops unboundedly. This extends ADR-0016's token-aware rule from plain text to Monospace Spans and makes the grammar, not prose lists, the source of truth.

The grammar is backed by checked-in evidence fixtures captured from a real Jira renderer; rules without evidence are not added. Inside a Monospace Span every observed hazard is neutralized with decimal character references because inline code is literal by definition and the references are the only encoding Jira leaves untouched: Text Effect pairs, `??citation??`, `{` `}` `\` (a trailing `\` or a `{}` pair is otherwise silently consumed), space-surrounded `--`/`---`, emoticon tokens, tabs and edge spaces, `[...]` link syntax, and cell-splitting `|`. Complete `http`, `https`, `ftp`, and `mailto` URLs are deliberately left to Jira's autolinker because the visible text is unchanged. A Monospace Span adjacent to a word character is separated with U+200B, which Jira treats as a boundary; Jira-to-JFM conversion strips only a U+200B touching the outside of `{{` or `}}`. Plain text keeps ADR-0016's scope (Text Effects plus existing structural characters) because emoticons and dashes in prose are Jira-flavored semantics that must survive the Jira → JFM → Jira round-trip.

Jira-to-JFM conversion continues to map every Monospace Span to inline code. When the body carries a Text Effect or link that Jira would have rendered, the converter keeps it literal and reports a conversion warning; emoticon and dash reinterpretations inside a Monospace Span are treated as Jira misrendering of code and stay silent. Warning-free inline code conversion is byte-lossless for the body, which is stricter than the specification's general stabilization guarantee. Hand-written escape allowlists keyed on the JFM autolink regexp or bracket shapes are rejected because they encode guesses about a different grammar and drift independently of the parser.
